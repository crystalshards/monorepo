**Date:** 2025-10-09
**Investigator:** CrystalShards Agent
**Issue:** Application pods not starting within Kubernetes timeout

### Root Cause Analysis (Based on Configuration Review)

While I cannot directly inspect the cluster, I have analyzed the Terraform configuration and identified several potential issues:

#### 1. Dependency Chain Issues

Applications depend on multiple infrastructure components that must be ready before the apps can start:

**CrystalShards:**
- PostgreSQL cluster (`crystalshards-postgres`) via CloudNativePG
- PostgreSQL app secret (`crystalshards-postgres-app`) generated by CNPG
- Shared Redis (`shared-redis.infrastructure.svc.cluster.local`)
- Shared MinIO (`shared-storage-hl.infrastructure.svc.cluster.local`)
- MinIO user secret (`shared-storage-user-1` in `infrastructure` namespace)

**CrystalDocs:**
- PostgreSQL cluster (`crystaldocs-postgres`) via CloudNativePG
- PostgreSQL app secret (`crystaldocs-postgres-app`) generated by CNPG
- Shared MinIO for documentation storage
- MinIO user secret (`shared-storage-user-1` in `infrastructure` namespace)

**CrystalGigs:**
- PostgreSQL cluster (`crystalgigs-postgres`) via CloudNativePG
- PostgreSQL app secret (`crystalgigs-postgres-app`) generated by CNPG

**CrystalBits:**
- PostgreSQL cluster (`crystalbits-postgres`) via CloudNativePG
- PostgreSQL app secret (`crystalbits-postgres-app`) generated by CNPG

#### 2. Potential Root Causes

Based on the 20-minute timeout (`progress_deadline_seconds = 1200`) configured in all deployments:

**a) CNPG Cluster Not Ready**
- CloudNativePG takes time to provision PostgreSQL clusters
- App secrets are only created after the cluster is fully initialized
- If CNPG is slow or stuck, app pods cannot start because secrets are missing

**b) Infrastructure Dependencies Not Ready**
- Shared Redis in `infrastructure` namespace may not be running
- Shared MinIO tenant may not be fully provisioned
- MinIO user secrets may not exist yet

**c) Image Pull Issues**
- GKE Autopilot may be slow to pull images from Artifact Registry
- Image may not exist: `us-docker.pkg.dev/${project_id}/crystalshards/{app}:{tag}`
- Registry authentication may be missing

**d) Application Startup Failures**
- Lucky apps may fail to start if database migrations fail
- Health check endpoints may not respond within timeout
- Initial delay (60s liveness, 30s readiness) may be insufficient

**e) Network Policies**
- Apps have network policies that may block traffic to dependencies
- Cross-namespace communication to `infrastructure` may be blocked

#### 3. Configuration Observations

**Positive:**
- Reasonable resource limits (512Mi-2Gi memory, 250m-1000m CPU)
- Proper health checks configured
- Security contexts properly set
- Increased timeouts for GKE Autopilot

**Concerns:**
- No init containers to wait for dependencies
- No explicit dependency readiness checks
- Terraform data sources depend on secrets existing (chicken-egg problem)
- No startup probes (only liveness and readiness)

### Potential Fixes (Hypothesis-Based)

#### Fix 1: Add Init Containers to Wait for Dependencies

Add init containers to each deployment that wait for:
- PostgreSQL readiness
- Redis readiness (crystalshards only)
- MinIO readiness (crystalshards, crystaldocs)

Example:
```yaml
initContainers:
- name: wait-for-postgres
  image: postgres:15
  command:
  - sh
  - -c
  - |
    until pg_isready -h crystalshards-postgres-rw -p 5432; do
      echo "Waiting for PostgreSQL..."
      sleep 5
    done
```

#### Fix 2: Use Startup Probes

Add startup probes to allow more time for initial startup:

```hcl
startup_probe {
  http_get {
    path = "/api/health"
    port = 3000
  }
  initial_delay_seconds = 10
  period_seconds        = 10
  failure_threshold     = 30  # 5 minutes total
}
```

#### Fix 3: Verify Operator Status

Ensure all operators are running:
- CloudNativePG operator
- Redis operator
- MinIO operator

Check operator logs for errors.

#### Fix 4: Pre-create Secrets

Instead of using Terraform data sources that depend on CNPG-generated secrets, use a two-phase approach:
1. Deploy operators and PostgreSQL clusters
2. Wait for CNPG to generate secrets
3. Deploy applications

Or use dummy secrets initially and update them after CNPG is ready.

#### Fix 5: Network Policy Review

Verify network policies allow:
- App → PostgreSQL (within namespace)
- App → Redis (cross-namespace: crystalshards → infrastructure)
- App → MinIO (cross-namespace: crystalshards/crystaldocs → infrastructure)
